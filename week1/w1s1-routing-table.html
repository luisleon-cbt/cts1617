How a router decides: reading the routing table

In CTS1380 you ended on a router that joined two VLANs on one switch. Every network it needed was plugged straight into it, so it never had to be told anything. This week the networks move apart, and a router that cannot see a destination simply drops the packet. You will configure two routers below, watch a ping fail in two different ways, and fix both. This page is interactive: click each bar to expand it.

The core idea

A router forwards a packet by looking up its destination address in the routing table, and nothing else. If no entry matches, the packet is dropped. A new router knows only the networks its own working interfaces touch. Every other network has to be taught, by you with a static route or by a routing protocol, and every conversation needs a route in both directions, because the reply is a separate packet making its own trip.

    The Building Blocks — Click to Explore

    ▸ Two entries appear for every interface that is up: C and L

    Give an interface an address and bring it up, and the router adds two lines. The C line is the whole network the interface sits on. The L line is the router's own address as a /32 host route, so traffic addressed to the router itself is recognised and never forwarded.

    C        10.12.107.0/30 is directly connected, GigabitEthernet0/1
L        10.12.107.1/32 is directly connected, GigabitEthernet0/1

    Both lines exist only while the interface is up at both layers. Shut the interface, or unplug the far end, and they vanish, along with every static route whose next hop lived on that network. Try it in the console: shut R1's G0/1 and read the table again.

    ▸ One line of show ip route, read from left to right 
    S        10.2.107.0/24 [1/0] via 10.12.107.2

    S is the source: static. 10.2.107.0/24 is the destination network. In the brackets, 1 is the administrative distance (how trusted the source is) and 0 is the metric (how far, by that source's measure). via 10.12.107.2 is the next hop: the neighbour's address, never your own.

    Above the entries, Gateway of last resort is not set tells you there is no default route. When you see that line, anything not listed explicitly will be dropped.

    ▸ The most specific match wins, wherever it sits in the table

    If 10.0.0.0/8, 10.3.0.0/16 and 10.3.107.0/24 all contain the destination, the /24 is used because it describes the destination most precisely. Prefix length is compared first. Administrative distance only matters when two sources offer the same prefix, which is Topic 1.3.

    This is why a default route (0.0.0.0/0) never steals traffic from a specific route: at /0 it is the least specific entry possible, and it is used only when nothing else matches.

    ▸ Connected routes are trusted most, then static routes

    Each route source has an administrative distance. Connected is 0 and static is 1, which is why a static route you type can never displace a directly connected network. Dynamic protocols sit higher: OSPF, the subject of Week 2, is 110.

    You will use this ranking deliberately in Session 3, when a static route with a raised distance waits silently as a backup.

    ▸ No route means drop, and the two symptoms look different

    If the first router has no route, it tells the sender. A Cisco router's ping prints U.U.U, and a PC reports Destination host unreachable from the router's address. You know exactly where the problem is.

    If the request gets through and the reply has no route home, nobody is told anything. The ping prints dots, and a PC reports Request timed out. That silence is the harder case, and it almost always means a missing return route on a router you have not looked at yet.

    ▸ Every ping is two one-way trips

    A static route is one-way: it helps packets leaving this router toward that network and does nothing for traffic coming back. For PC-A and PC-B to talk, R1 needs a route to PC-B's network and R2 needs a route to PC-A's network. Forgetting the second half is the most common static routing fault in any course, including this one.

    Plan routes on paper as pairs. For every remote network a router needs, ask which router needs the way back.

    Walk it through: one ping, five decisions

    Step 1: PC-A decides the destination is not local

    PC-A (10.1.107.10/24) wants 10.2.107.10. It compares the destination with its own network: 10.2.107.10 is not inside 10.1.107.0/24, so PC-A sends the packet to its default gateway, 10.1.107.1, which is R1's G0/0. PC-A does no routing at all. Its only decision is "local or not".

    Step 2: R1 has no matching entry and drops the packet

    R1 looks up 10.2.107.10. Its table holds only C and L entries for 10.1.107.0/24 and 10.12.107.0/30. Nothing contains the destination and there is no gateway of last resort, so R1 drops the packet and sends an unreachable message back. PC-A prints Reply from 10.1.107.1: Destination host unreachable. The router named itself as the place the trip ended.

    Step 3: A static route on R1 gets the request across 
    R1(config)# ip route 10.2.107.0 255.255.255.0 10.12.107.2

    Now the lookup matches. R1 then looks up the next hop itself, 10.12.107.2, finds it inside the connected 10.12.107.0/30, and sends the packet out G0/1. R2 receives it, sees 10.2.107.0/24 as directly connected, and delivers it to PC-B.

    Step 4: The reply dies at R2, and PC-A only sees silence

    PC-B replies to 10.1.107.10 through its gateway, R2. R2 has no entry for 10.1.107.0/24, so the reply is dropped. The unreachable message R2 would send is addressed to PC-B, not PC-A, so PC-A hears nothing and prints Request timed out. The request succeeded and the ping still failed, which is exactly why a failed ping alone does not tell you which router is wrong.

    Step 5: The return route completes the conversation 
    R2(config)# ip route 10.1.107.0 255.255.255.0 10.12.107.1

    Replies now have a way home. tracert 10.2.107.10 from PC-A lists R1, then R2, then PC-B. Verify with show ip route on both routers before you trust the ping: the ping proves the path works today, and the tables prove why it works.
