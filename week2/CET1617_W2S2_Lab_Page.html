Configuring OSPF deliberately: interface mode, passive interfaces, and loopbacks

Today you choose exactly which interfaces speak OSPF and how. The payoff moment is the ring: R1's table lists LAN C twice at equal cost, and you can prove traffic uses both paths.

Personalization is graded. Your student number (SN) runs from 1 to 99. Every independent build uses X = 100 + SN as the third IPv4 octet (and in the IPv6 prefix), and every hostname ends in your initials, for example R1-LDL. Week 2 adds two more: your OSPF process ID is your student number, and your router IDs are X.0.0.n, where n is the router number (R1 is X.0.0.1). Submissions whose personalized values do not match your assignment earn zero for that lab, no exceptions. Ticket files are pre-built on the instructor base (third octet 100) and are not re-addressed: your personalization on a ticket is renaming every router to end in your initials before you capture anything.

Objectives

  1. Enable OSPF with network statements and with interface commands, and identify which method was used from show output.
  2. Calculate wildcard masks that match exactly the intended interfaces.
  3. Configure passive interfaces individually and with passive-interface default.
  4. Advertise loopback interfaces and interpret /32 OSPF routes and equal-cost paths.
  5. Diagnose a missing adjacency caused by a passive transit interface.

LAB 2 · GUIDED

Interface mode, passive LANs, and loopbacks

Completion credit: submit your .pkt, no screenshots required. Work on your warm-up file.

  1. On R3, remove its network statements one at a time with no network ... and watch its adjacencies drop.
  2. Enable R3's interfaces from interface mode instead:
    R3(config)# interface g0/1
R3(config-if)# ip ospf SN area 0
R3(config-if)# interface g0/2
R3(config-if)# ip ospf SN area 0
R3(config-if)# interface g0/0
R3(config-if)# ip ospf SN area 0
    Replace SN with your process ID. The adjacencies return. show ip ospf interface g0/1 on real IOS says Attached via Interface Enable; Packet Tracer may shorten that output, so also confirm the command under each interface in show running-config.
  3. Make every LAN interface passive: passive-interface g0/0 under each router's OSPF process. Confirm with show ip protocols that the LANs are listed as passive, and with show ip route on another router that they are still advertised.
  4. Add Loopback0 on each router (10.255.X.n/32) and advertise it: a network statement with a 0.0.0.0 wildcard on R1 and R2, ip ospf SN area 0 on R3's loopback.
  5. On R1, find the loopbacks as /32 O routes, and find the equal-cost pair for the R2 to R3 link. Save everything.

Passive by default

  2. Bring them back with no passive-interface on the two links to other routers only.
  3. Confirm LAN A and R1's loopback are still advertised, now as passive interfaces.
  4. Write one sentence in your PDF on when this style is safer than listing passive interfaces one by one.

Troubleshooting

  • An adjacency vanished the moment you typed passive-interface default: expected. Every interface is now passive until you exempt the links with no passive-interface.
  • A link between routers shows 0/0 in show ip ospf interface brief: that interface is passive.
  • A loopback appears as /32 although you configured /24: OSPF advertises loopbacks as host routes. That is normal.
  • Only one path to a network where you expected two: the costs are not equal. Compare the costs in show ip ospf interface brief along both paths.
  • An interface configured with ip ospf is not in OSPF: the process ID in the interface command differs from the running process.
  • Traffic takes a longer path although every link is up: an adjacency is missing on the shorter path. Check neighbors on both ends of it.
