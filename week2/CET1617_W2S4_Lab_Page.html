LAB 2 · GUIDED

One default route for the whole area

Completion credit: submit your .pkt, no screenshots required. Build the edge network from the table with demo value X = 107, process 1, router IDs 1.1.1.1 to 3.3.3.3, LANs passive. The ISP router gets ip route 10.0.0.0 255.0.0.0 198.51.100.2 and no OSPF.

  1. On R1 and R3, show ip route: Gateway of last resort is not set. PC-A cannot reach 203.0.113.10.
  2. On R2, add the static default and originate it:
    R2(config)# ip route 0.0.0.0 0.0.0.0 198.51.100.1
R2(config)# router ospf 1
R2(config-router)# default-information originate
  3. On R1 and R3, show ip route again: O*E2 0.0.0.0/0 [110/1] and a gateway of last resort. PC-A now browses to 203.0.113.10.
  4. Now the failure Week 1 could not handle. In Packet Tracer, delete the cable between SW13 and R3. R1's G0/2 stays up. Wait for R1 to log the neighbor down (up to 40 seconds), then traceroute from PC-A to PC-C: the path now crosses R2.
  5. Reconnect the cable. On R1, add ip route 10.3.107.0 255.255.255.0 10.13.107.2, delete the SW13 to R3 cable again, and ping PC-C from PC-A. It fails: the static route stays installed and overrides OSPF. Remove the static route, reconnect, and save.

LAB 3 · SEMI-GUIDED

Break an adjacency five ways

New file: two routers on one /30, OSPF FULL between them. Break the adjacency one way at a time, record what you see, and repair it before the next.

  1. Draw a table on paper with a row for each fault: area mismatch, hello interval mismatch, subnet mask mismatch, passive interface, duplicate router ID. Add columns for what show ip ospf neighbor showed, what show ip ospf interface showed, and the fix.
  2. Introduce each fault on one router only, fill in the row, then repair it.
  3. For the duplicate router ID, remember that the new ID needs clear ip ospf process to take effect.
  4. Confirm the adjacency is FULL again at the end.

LAB 4 · INDEPENDENT BUILD

The OSPF edge network

Requirements sheet only. Build the edge network from the table on your own values: X = 100 + SN, process ID SN, router IDs X.0.0.1 to X.0.0.3. The ISP side is the provider's and is the same for everyone.

  • R2 is the only router with a static route. It points at the ISP and is advertised into OSPF, so R1 and R3 learn a default route from OSPF alone.
  • The ISP routes 10.0.0.0/8 back to R2 with one static route. It does not run OSPF.
  • Every LAN interface is passive.
  • PC-A and PC-C both load the WEB page by browsing to 203.0.113.10.
  • When the cable between SW13 and R3 is removed, LAN A still reaches LAN C through R2 without any configuration change.

Troubleshooting

  • Other routers get no O*E2 default: the originating router has no default route of its own, or default-information originate is missing.
  • The default route arrives but the web page does not load: the ISP has no route back to 10.0.0.0/8, or HTTP is off on WEB.
  • After the cable is removed, the traceroute may reroute within seconds while R1 still lists R3 as a neighbor: R3 lost its own port and told the area through R2. The neighbor entry disappears when the 40-second dead timer expires. Capture after the neighbor-down message so both appear in your evidence.
  • Traffic still fails after the neighbor went down: a static route to the same network is overriding OSPF. Check the code at the start of the route line.
  • Two routers cabled together are not neighbors: compare show ip ospf interface on both ends, area and timers first.
  • A fix did not restore the ping: there may be a second fault. Recheck every symptom in the ticket after every change.
