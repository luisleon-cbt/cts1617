OSPF from the ground up: neighbors and your first OSPF routes

Last week every route was typed by hand. Today the routers learn them. The payoff moment is Lab 2's third router coming up: two ADJCHG messages scroll past, and routes you never typed appear in every table.

Personalization is graded. Your student number (SN) runs from 1 to 99. Every independent build uses X = 100 + SN as the third IPv4 octet (and in the IPv6 prefix), and every hostname ends in your initials, for example R1-LDL. Week 2 adds two more: your OSPF process ID is your student number, and your router IDs are X.0.0.n, where n is the router number (R1 is X.0.0.1). Submissions whose personalized values do not match your assignment earn zero for that lab, no exceptions. Ticket files are pre-built on the instructor base (third octet 100) and are not re-addressed: your personalization on a ticket is renaming every router to end in your initials before you capture anything.

Objectives

  1. Explain how OSPF routers discover neighbors and build a shared link-state database.
  2. Configure single-area OSPFv2 with a planned router ID and exact network statements.
  3. Verify adjacencies with show ip ospf neighbor and learned routes with show ip route ospf.
  4. Interpret an OSPF route's administrative distance, cost, next hop, and equal-cost paths.
  5. Diagnose an interface that is not participating in OSPF.

LAB 2 · GUIDED

The Week 1 triangle, now with OSPF

Completion credit: submit your .pkt, no screenshots required. Open a copy of your Week 1 Session 1 Lab 4 triangle. For this lab only, use process ID 1 and router IDs 1.1.1.1, 2.2.2.2 and 3.3.3.3, so your output matches Topic 2.1.

  1. Remove every static route: on each router, show running-config to list them, then no ip route ... for each one. Confirm that PC-A can no longer reach PC-C.
  2. On R1, start OSPF and set the router ID first:
    R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
R1(config-router)# network 10.1.X.0 0.0.0.255 area 0
R1(config-router)# network 10.12.X.0 0.0.0.3 area 0
R1(config-router)# network 10.13.X.0 0.0.0.3 area 0
  3. Configure R2 the same way with its three networks. Watch R2's console for %OSPF-5-ADJCHG ... from LOADING to FULL.
  4. Configure R3. Each router now logs two adjacencies.
  5. Run show ip ospf neighbor on every router: two neighbors each, all FULL, with DR and BDR roles on each /30.
  6. Run show ip route ospf on R1. Find LAN C at cost 2 and the R2 to R3 link listed twice at equal cost. Ping PC-C from PC-A, and save every configuration.

Troubleshooting

  • No ADJCHG message and no neighbor: the network statement does not match the interface. Check show ip ospf interface brief: an interface missing from that list is not running OSPF.
  • The router ID is not the one you configured: you set it after OSPF had already chosen one. Run clear ip ospf process and answer yes.
  • A network statement does not match the interface you expected: compare the wildcard in show running-config with your paper plan. Some IOS versions quietly convert a subnet mask typed in place of the wildcard, so always check what was actually stored.
  • A network statement with a 0.0.0.0 wildcard matches only an interface's own address, never a network address.
  • Neighbors are FULL but a LAN is missing from other routers' tables: the LAN interface itself is not in OSPF.
  • Routes still show S instead of O: an old static route is still configured, and distance 1 beats OSPF's 110.
