Shared segments: DR and BDR election, network types, and cost

Four routers on one switch, and an election result nobody designed. The payoff moment is the neighbor table after your clears: the DR you chose, the BDR you chose, and the routers you excluded sitting at 2WAY exactly as planned.

Campus session. The guided lab depends on the order in which you configure the routers, so follow the order exactly. In the independent build, priorities alone do not move an existing DR: plan the clears that make your design take effect.

Personalization is graded. Your student number (SN) runs from 1 to 99. Every independent build uses X = 100 + SN as the third IPv4 octet (and in the IPv6 prefix), and every hostname ends in your initials, for example R1-LDL. Week 2 adds two more: your OSPF process ID is your student number, and your router IDs are X.0.0.n, where n is the router number (R1 is X.0.0.1). Objectives

  3. Configure the point-to-point network type and explain its effect.
  4. Set a consistent reference bandwidth and use interface cost to select a path.
  5. Diagnose an adjacency failure on a shared segment caused by a mismatched parameter.

LAB 2 · GUIDED

Watch an election go wrong, then fix it

Completion credit: submit your .pkt, no screenshots required. Build the shared segment from the table with demo value X = 107, process 1 and router IDs 1.1.1.1 to 4.4.4.4. Power the routers on and configure OSPF on R1 first, then R2, R3 and R4, in that order. After R1, wait until show ip ospf interface g0/1 on R1 shows State DR (about 40 seconds) before you configure R2, and wait for R2 to show BDR before you configure R3. Configure them faster and the election runs among whoever is present, with a different result.

  1. On R3, show ip ospf neighbor. R1 is DR and R2 is BDR, although R4 has the highest router ID. R4 is 2WAY/DROTHER, which is normal.
  2. On R4's G0/1, ip ospf priority 255. Check again: nothing changed. The election does not preempt.
  3. Run clear ip ospf process on R1 and answer yes to the Reset ALL OSPF processes prompt, then do the same on R2. Check from R3: R4 is DR now.
  4. On R3's G0/1, ip ospf priority 0, then clear ip ospf process on R3. R3 is now a DROTHER and can never be elected.
  5. On the R1 to R4 direct link, set ip ospf network point-to-point on both ends. show ip ospf neighbor on R1 shows R4 as FULL/ - on G0/2: no DR on that link any more. (Packet Tracer 8.2 accepts this command. If yours rejects it, note it in your file and continue.)
  6. Save all four routers.

LAB 3 · SEMI-GUIDED

Make the cost mean something

Same file. The default reference bandwidth makes every interface cost 1.

  1. On all four routers, set auto-cost reference-bandwidth 10000. Read the warning IOS prints and why it asks for consistency.
  2. On R1, show ip ospf interface brief: every GigabitEthernet interface now costs 10.
  3. Traceroute from PC-A to PC-D. Note which path it takes and whether R1 has one or two routes to LAN D.
  4. Raise the cost on R1's G0/2 to 100, traceroute again, and explain the change in one sentence.

📸 Checkpoint 3A (2 pts). Screenshot required: R1's show ip ospf interface brief showing cost 10 on the segment and 100 on G0/2.

📸 Checkpoint 3B (2 pts). Screenshot required: PC-A's two traceroutes to PC-D, before and after the cost change, one per capture.

Troubleshooting

  • Two routers show 2WAY/DROTHER to each other: normal on a shared segment. Only the DR and BDR go FULL with everyone.
  • You raised a priority and the DR did not change: the election does not preempt. Clear the process on the current DR and BDR.
  • No router becomes DR: every router on the segment has priority 0.
  • IOS printed a reference bandwidth warning: expected. Enter the same value on every router or costs become inconsistent.
  • A router can ping across the segment but forms no adjacency: compare the mask, area, and timers in show ip ospf interface on both ends.
  • Traffic keeps using both paths after a cost change: the costs are still equal somewhere. Add the costs along each path, from the sending router.
