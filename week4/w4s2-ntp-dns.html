NTP and DNS: the right time and the right name

Two quiet services decide whether the rest of your management tools can be trusted. Without NTP, every router keeps its own idea of the time, often a date in 1993, and a log file that says an interface failed "at midnight on March 1" is useless when you are rebuilding what happened during an outage. Without DNS, every person and every device has to remember addresses. This topic sets both up and shows what goes wrong when they are missing. This page is interactive: click each bar to expand it.

The core idea

NTP synchronizes device clocks to a reference over UDP port 123. A router pointed at a server with ntp server becomes a client one stratum below it, and can serve time to other routers in turn. DNS translates names into addresses over UDP port 53. A router uses ip name-server to resolve names, and by default it also tries to resolve anything you mistype at the prompt, which is why labs turn that off with no ip domain-lookup.

Give the network one clock and one phone book

SRV runs both an NTP service and a DNS service. R1 and R2 still show the clock they booted with, and nobody can reach anything by name. Synchronize R1 to SRV, let R2 take its time from R1, and make names work on the routers and on PC-A.

    The Building Blocks — Click to Explore

    ▸ Why every device needs the same time

    Log timestamps only help if every device agrees on the time: an outage report built from three routers whose clocks differ by hours or decades cannot tell cause from effect. Certificates, SSH keys, and time-based rules also depend on a correct clock. A router with no time source shows a leading asterisk in show clock, which means the time is not authoritative.

    ▸ NTP clients, servers, and stratum

    A reference clock such as GPS is stratum 0. A server attached to it is stratum 1, a device synchronized to that server is stratum 2, and so on down the chain, up to 15. Stratum 16 means unsynchronized. Every router that is synchronized can serve time to others, so a large network points a few core routers at an external server and everything else at those routers.

    ▸ Configuring and verifying an NTP client 
    R1(config)# ntp server 10.3.107.10
R1(config)# clock timezone EST -5
R1# show ntp status
Clock is synchronized, stratum 2, reference is 10.3.107.10

    show ntp associations lists every configured server, with an asterisk on the one in use. Real NTP takes up to several minutes to synchronize; this console and Packet Tracer are faster. clock set in privileged mode sets the time by hand, which is a fallback, not a substitute.

    ▸ DNS turns names into addresses

    A client asks its configured DNS server, usually over UDP port 53, for the address of a name. The server answers from its own records or asks other servers on the client's behalf. An A record maps a name to an IPv4 address and an AAAA record to an IPv6 address. nslookup on a PC shows which server answered and what it said.

    ▸ The router as a DNS client: ip name-server and ip host 
    R1(config)# ip domain-name cbt.lab
R1(config)# ip name-server 10.3.107.10
R1(config)# ip host SRV1 10.3.107.10

    With a name server, ping web.cbt.lab works from the router, and a short name like web has the domain appended. ip host adds a static entry that needs no server at all, and it is checked first. show hosts lists both.

    ▸ Why a typo freezes the router, and no ip domain-lookup

    At the exec prompt, IOS treats a single unknown word as the name of a host to telnet to. With lookups on and no name server, it broadcasts the query and waits several seconds before giving up. Labs usually add no ip domain-lookup to stop that; the cost is that the router can no longer resolve names at all. In production, configure a real name server instead.

    Walk it through: why the outage report had the wrong time

    Step 1: Three routers, three clocks

    R1 has been up for two days and shows March 3, 1993. R2 was rebooted this morning and shows March 1. Neither has ever had a time source, so both carry the asterisk. Their logs are internally consistent and useless together.

    Step 2: R1 synchronizes to the stratum 1 server

    ntp server 10.3.107.10 on R1. show ntp status reports synchronized, stratum 2, and show clock shows today's date without the asterisk.

    Step 3: R2 takes its time from R1

    ntp server 10.12.107.1 on R2. R2 becomes stratum 3. Only R1 talks to the external server; the rest of the network follows R1.

    Step 4: Local time for the people reading the logs

    clock timezone EST -5 on both routers. NTP still runs in UTC underneath; the time zone only changes what is displayed, so every router shows the same local time.

    Step 5: Names instead of addresses

    ip name-server 10.3.107.10 lets the routers ping web.cbt.lab. PC-A already uses SRV as its DNS server, so nslookup r2.cbt.lab and ping r2.cbt.lab work there too. Next session, the same names and the same clock make the syslog server readable.
